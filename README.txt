Windows setup
=============
1. Install Python 3.11 or 3.12.
2. Extract this ZIP.
3. Double-click run_windows.bat.
4. Wait for the setup window to install missing packages.
5. Select a source folder and a separate output folder.

Startup setup window
--------------------
`run_windows.bat` creates a self-contained `.venv` inside this application
directory on first launch. `startup.py` displays progress while checking package
versions and installs only missing or incompatible components into that local
environment. The app starts only after the setup succeeds, and errors are shown
in the same window.
Package installation uses `--no-cache-dir` because Windows antivirus or another
Python process can lock files in the shared user pip cache.
The installer also redirects temporary pip files to `.pip-tmp` inside this
directory and retries an access-denied installation up to three times.
On the first launch, the GPU ONNX Runtime and CUDA 13.2 runtime packages are
aligned once after legacy CUDA 12 wheels and the CPU ONNX Runtime package are
removed. The `.gpu_runtime_initialized` marker prevents repeating that expensive
setup on later launches. Set `TWITTER_SORTER_FORCE_GPU_REPAIR=1` before starting
to force a repair again. If CUDA still cannot be activated, the application
explicitly falls back to CPU mode.

GPU
---
NudeNet (ONNX Runtime) and PyTorch now use the same CUDA 13.2 / cuDNN 9 runtime.
ONNX Runtime 1.27+ is built for CUDA 13, and this project pins
`onnxruntime-gpu==1.31.1`. The startup script removes old `nvidia-*-cu12`
wheels, installs the missing `nvidia-curand` library, and checks the required
CUDA 13 DLLs and CUDAExecutionProvider. For GPU processing, install a current
NVIDIA display driver and the latest Microsoft Visual C++ runtime first.
If CUDA is unavailable, the application starts in CPU mode.

Pre-processing button
---------------------
The button scans the source tree and asks before deleting files whose basename starts with
".trashed-" or whose name ends in "(digits)" immediately before the extension, e.g. image(1).jpg.
Deletion is permanent and does NOT use the Windows Recycle Bin. Review the preview carefully.

The sorter also skips these filename patterns even if the cleanup button is not used.
Classification uses NudeNet 3.4.2 NudeDetector locally; it is a heuristic and may misclassify images.

Local tagging, embeddings, clustering and search
-------------------------------------------------
The new pipeline is command-line based so it can process tens of thousands of
images without keeping them in the GUI. It stores paths, Florence-2 captions, CLIP
embeddings and cluster IDs in a local SQLite database and resumes safely.

Install the optional CLIP runtime once:

    python -m pip install torch transformers

Florence-2 also requires `timm` and `einops`; the startup setup installs these
automatically from `requirements.txt`.

Run these commands from this folder:

    python image_pipeline_cli.py analyze "D:\images" --database "D:\images.sqlite3"
    python image_pipeline_cli.py cluster --database "D:\images.sqlite3" --clusters 40
    python image_pipeline_cli.py search "ケモノ 背景 線画" --database "D:\images.sqlite3"
    python image_pipeline_cli.py search "a furry character in a forest" --semantic --database "D:\images.sqlite3"

The first model load may download from Hugging Face; subsequent runs use the
local cache. Florence-2 captions are stored as generated by Florence-2.
`search` without `--semantic` performs fast local keyword search;
`--semantic` translates Japanese queries locally and compares them with stored
CLIP vectors.
Clustering treats images that the continuity checker matched as one unit: the
whole sequence group receives the same cluster, and its centroid is weighted by
the group's boundary match score. The cluster count is taken from the
`--clusters` option (GUI: the `クラスタ数` field). If the requested count is
larger than the number of matcheable units, each unit becomes its own cluster.

GUI
---
The same workflow is available in the `タグ・特徴量・検索` tab of the existing
Tkinter application. Select the image folder and SQLite file, then use the
buttons for CLIP analysis, Florence-2 captions, clustering, keyword search, or
NSFW score analysis. The separate continuous-image checker sorts files by their Windows file
modification time, considers neighbors within 1% height difference updated within
10 seconds,
groups up to four contiguous files before ordering them by boundary score, stores
sequence order, and
search results show one of the top 20 groups at a time
and can be switched with the mouse wheel. Long-running operations run in the
background and show progress in the tab.
After sequence detection, use `グループを確認` to open one group at a time.
The viewer keeps only the current group and its immediate neighbors in memory;
use the bottom buttons, left/right arrow keys, or the mouse wheel to switch.
Use `手動でグループ追加` to browse the selected folder four images at a time,
review each image's registration status, and register two to four checked images
in folder order. Existing
sequence groups can be removed from the same viewer without deleting image data.
The viewer also lets you move a selected image up or down and save the new
sequence order.
The `画像サムネイル一覧` tab provides a full-width, gapless square-thumbnail
browser. It shows one to twelve images per row, reports the clicked image's
folder-order number at the bottom, supports the mouse wheel and up/down keys,
preloads three rows before and after the visible range, and releases thumbnails
outside that cache range.
Switch `表示元` between `フォルダ` and `SQLiteクラスタ` to review clustered
analysis results in the same browser. Cluster mode lists every
`cluster_id` with its row count, has previous/next buttons for stepping through
clusters, and accepts an optional SQL filter. A full read-only `SELECT`/`WITH`
query must return a `path` column; any other text is combined with the selected
cluster as an additional `WHERE` expression. The optional SQL field is only
used in cluster mode. Set `クラスタ数` and press `再分類` to re-run clustering
for the selected database without leaving the thumbnail tab; sequence groups
stay together regardless of the requested count.
For Florence-2 captions, run:

    python image_pipeline_cli.py caption "D:\images" --database "D:\images.sqlite3"

The schema is shared, so Florence-2 captions can be searched together with paths.
All image analysis is local after model files have been downloaded.

GPU acceleration
----------------
CLIP and Florence-2 use the same local CUDA-capable PyTorch installation and move their
models and inputs to `cuda`. If a provider or CUDA device cannot be initialized,
each operation falls back to CPU without changing the saved database format.
The CUDA runtime version check and forced GPU reinstall run only during the first
launch. Later launches reuse `.gpu_runtime_initialized`; set
`TWITTER_SORTER_FORCE_GPU_REPAIR=1` to run the repair again intentionally.
The shared selection logic is in `gpu_runtime.py`.
PyTorch is installed separately as the matching CUDA 13.2 trio:
`torch`, `torchvision`, and `torchaudio` from the official `cu132` index.
